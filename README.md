## Что это такое

Пользователь вводит пароль — приложение **в реальном времени** показывает его
надёжность по четырём уровням из ТЗ: **Faible / Moyen / Fort / Très fort**.

**Главное архитектурное решение: анализ на 100 % локальный.**
Пароль обрабатывается в браузере и **никогда** не уходит по сети, не пишется в
хранилище, не попадает в логи. Проверялка паролей, которая отправляет пароль на
сервер, — сама по себе дыра в безопасности. Это стоит сказать на защите.

## 🔧 Что где менять

### Поменять правила уровней

`miniapp/strength.js`, самый верх файла — блок `CONFIG`:

```js
LEVELS: [
  { id: 'tres_fort', index: 3, minLength: 16, minTypes: 4 },
  { id: 'fort',      index: 2, minLength: 12, minTypes: 3 },
  { id: 'moyen',     index: 1, minLength: 8,  minTypes: 2 },
  { id: 'faible',    index: 0, minLength: 0,  minTypes: 0 },
],
MIN_LENGTH_CRITERION: 8,
```

Меняешь число — **меняется всё сразу**: и экран, и бот, и подпись «Au moins 8
caractères», и счётчик «12 / 8». Ничего больше править не надо.
После правки прогони `npm test` — тесты покажут, что сломалось.

### Поменять тексты

`miniapp/i18n.js` — три блока: `fr`, `ru`, `en`. Французский главный.

### Поменять цвета уровней

`miniapp/style.css`, строка ~37:

```css
--c-faible: #ff453a;    --c-moyen: #ff9f0a;
--c-fort:   #30d158;    --c-tres:  #a855f7;
```
`--c-*-ink` — более тёмный вариант того же цвета, **для текста**. Нужен, чтобы
надпись оставалась читаемой на светлой теме. Меняешь один — меняй и второй.

### Поменять эмодзи

`miniapp/index.html`, блок `<section class="scene">` — пять SVG-лиц
(`empty`, `faible`, `moyen`, `fort`, `tres_fort`). Анимации к ним —
в `style.css`, секция `@keyframes`.

### Другие настройки интерфейса

`miniapp/app.js`, блок `UI_CONFIG` в начале файла:

| Настройка | Что делает |
|---|---|
| `generatedLength: 20` | длина пароля из кнопки «Générer» |
| `autoDetectLanguage: false` | `true` — язык определится по браузеру. Сейчас всегда французский, потому что проект сдаётся во Франции |
| `lottieEnabled: false` | `true` — подхватывать настоящие Telegram-анимации из `miniapp/lottie/` |

## ⚠️ Противоречие в ТЗ и как оно решено

ТЗ описывает «Faible» тремя пунктами:

1. меньше 8 символов
2. только буквы или только цифры
3. **нет спецсимволов**

Пункт 3 **противоречит** правилу «Moyen», где достаточно 2 типов символов из 4.
Пароль `Bonjour123` — 10 символов, 3 типа: по правилу 2 это «Moyen», по пункту 3
это «Faible».

**Решение:** приоритет у правил 2–4 (они с конкретными числами и однозначны),
а пункты правила 1 читаются как *описание* случая по умолчанию. Пункты 1 и 2
при этом выполняются сами собой: меньше 8 символов → «Moyen» недостижим →
«Faible»; один тип символов → `typesCount = 1 < 2` → «Faible».

**Если препод потребует буквальное чтение** — одна строка в `strength.js`:

```js
STRICT_SPECIAL_CHAR_RULE: true,   // нет спецсимвола → сразу Faible
```

На это есть отдельный тест.

## Что сверх ТЗ (бонус)

Всё перечисленное помечено в интерфейсе значком **BONUS** и **никогда не меняет**
официальный уровень по ТЗ:

- проверка по списку самых частых паролей
- оценка энтропии в битах
- оценка времени перебора
- обнаружение повторов (`aaaa`) и последовательностей (`1234`, `azerty`)
- генератор надёжного пароля (на `crypto.getRandomValues`, не на `Math.random`)
- три языка интерфейса
- 164 юнит-теста

> Флаг `CONFIG.DOWNGRADE_COMMON_PASSWORDS` умеет понижать частый пароль до
> «Faible». По умолчанию `false` — именно чтобы **строго** соответствовать ТЗ.

## Безопасность

- `bot/.env` с токеном — в `.gitignore`, в репозиторий не попадает
- токен нужен **только** боту у тебя на машине; Mini App о нём вообще не знает
- если токен где-то засветился — `/revoke` у @BotFather, и он мгновенно мёртв
- бот, получив пароль в чат, предупреждает об опасности и пытается удалить
  сообщение; пароль не попадает в логи
